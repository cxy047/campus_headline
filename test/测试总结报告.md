## 四、缺陷定位方法

| 方法 | 应用案例 |
|------|----------|
| **Postman 接口探测** | 用普通用户 Cookie 直接 GET `/news/auditPass`，对比 `/video/auditPass`（已正确拦截），发现 RoleInterceptor 路径不匹配 |
| **F12 开发者工具** | 观察 Network 面板：CSRF 漏洞演示用纯 `<a href>` 触发写操作，Request Method 显示 GET |
| **代码静态扫描** | grep 所有 @GetMapping + "delete|audit|toggle" 关键词，发现写操作全用 GET |
| **SQL 数据校验** | 缺陷修复前后查 MySQL comment 表，验证删除操作是否带 userId 条件 |
| **Tomcat 版本对比** | 同一项目在 9.x vs 10.1 下 `/upload/xxx.jpg` 访问结果对比，定位 file: 前缀问题 |

## 五、测试结论

1. **质量评价**：本轮 58 条用例全部执行，51 通过、7 失败，通过率 87.9%；累计发现 10 个缺陷（S1×1、S2×5、S3×4），已修复 3 个并完成回归验证（BUG-001、BUG-002、BUG-004），其余 7 个处于待整改状态，修复率 30%。权限绕过类问题已收敛，但注册密码明文存储、视频审核状态、后端参数校验与异常处理仍不满足交付要求，当前版本不具备上线条件
2. **亮点**：主动发现 2 个权限绕过类 S2 缺陷（RoleInterceptor 路径不匹配、评论删除无身份校验），均通过 Postman 接口对比与代码定位确认，修复后完成回归；进一步通过边界值与异常场景暴露 6 个待整改缺陷，形成可复核的失败用例清单
3. **风险提示**：BUG-005 注册密码明文（S1）、BUG-008 管理员新增视频免审核直接发布、BUG-007 空标题/空内容落库、BUG-009 空评论返回 500、BUG-003 GET 写操作的 CSRF 风险，均尚未消除
4. **后续建议**：密码改为加盐哈希并强制重置历史账号；补 `@ControllerAdvice` 全局异常处理与参数校验；写操作改 POST + CSRF Token；统一视频新增状态为待审核；引入 JUnit 单测与 CI 自动化回归
