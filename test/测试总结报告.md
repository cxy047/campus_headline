## 三、缺陷统计

### 3.1 按严重度

| 严重度 | 数量 | 占比 | 说明 |
|--------|------|------|------|
| S1 致命 | 0 | 0% | 无崩溃/数据丢失 |
| S2 严重 | 2 | 50% | **权限绕过类安全缺陷** |
| S3 一般 | 2 | 50% | 规范/兼容性问题 |
| S4 建议 | 0 | 0% | — |
| **合计** | **4** | **100%** | |

### 3.2 按模块

| 模块 | 数量 | 严重度分布 |
|------|------|------------|
| 拦截器配置 (springmvc.xml) | 2 | S2 + S3 |
| 权限校验逻辑 (CommentController) | 1 | S2 |

### 3.3 按根因类型

| 根因类型 | 数量 | 说明 |
|----------|------|------|
| 配置路径写错 | 2 | RoleInterceptor mapping 与 Controller 真实路径不匹配 |
| 逻辑缺失 | 1 | CommentController.delete 无身份校验 |
| HTTP 方法不当 | 1 | 写操作用 @GetMapping |

## 四、缺陷定位方法

| 方法 | 应用案例 |
|------|----------|
| **Postman 接口探测** | 用普通用户 Cookie 直接 GET `/news/auditPass`，对比 `/video/auditPass`（已正确拦截），发现 RoleInterceptor 路径不匹配 |
| **F12 开发者工具** | 观察 Network 面板：CSRF 漏洞演示用纯 `<a href>` 触发写操作，Request Method 显示 GET |
| **代码静态扫描** | grep 所有 @GetMapping + "delete|audit|toggle" 关键词，发现写操作全用 GET |
| **SQL 数据校验** | 缺陷修复前后查 MySQL comment 表，验证删除操作是否带 userId 条件 |
| **Tomcat 版本对比** | 同一项目在 9.x vs 10.1 下 `/upload/xxx.jpg` 访问结果对比，定位 file: 前缀问题 |

## 五、测试结论

1. **质量评价**：4 个缺陷全部修复并回归通过，权限体系修复后安全边界清晰，达到课设交付标准
2. **亮点**：**主动发现了 2 个权限绕过类 S2 缺陷**（配置路径错误 + 逻辑缺失），均通过接口探测与代码定位确认，并在修复后完成回归验证
3. **风险提示**：未实现 CSRF Token 机制（仅通过改为 POST + 表单验证缓解）；全局异常处理 @ControllerAdvice 未实现，未捕获异常直接返回 JSP 错误页
4. **后续建议**：引入 JWT/Spring Security 替代 Session + Interceptor 方案；增加 JUnit 单元测试覆盖 Service 层核心逻辑；引入 GitHub Actions CI 自动回归
