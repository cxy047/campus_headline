## 0. 通用准备

### 0.1 启动项目

1. 环境：JDK 17、MySQL 8、Maven、Tomcat 10.1（**不能用 Tomcat 9**，项目使用 `jakarta.*`）。
2. 初始化数据库：命令行执行 `mysql -u root -p < Query.sql`，脚本会创建 `campus_headline` 库并写入初始数据。
3. 确认数据库账号：打开 `src/main/resources/jdbc.properties`，核对 `jdbc.username` / `jdbc.password` 与本机一致。
4. 打包并部署：

```powershell
mvn clean package
# 把 target/campus_headline.war 复制到 Tomcat 的 webapps 目录（仓库内已带 tomcat/）
Copy-Item "target\campus_headline.war" "tomcat\webapps\" -Force
# 启动
.\tomcat\bin\startup.bat
```

5. 访问 `http://localhost:8080/campus_headline/`，能看到首页新闻列表即为启动成功（直接访问 `index.jsp` 会被重定向到 `/index`）。
6. 每次改配置或重新打包后，先 `shutdown.bat` 再启动，避免半包部署导致 JSP 编译报错。

### 0.2 测试账号（来自 Query.sql 的 user 表）

| 账号 | 密码 | 角色 | user.id | 用途 |
|------|------|------|---------|------|
| `admin` | `123456` | admin | 1 | 审核、素材上传、删除等管理员操作 |
| `editor` | `123456` | admin | 3 | 备用管理员 |
| `student` | `123456` | user | 2 | 越权、普通用户发帖、点赞 |
| `zzzz` | `123456` | user | 4 | 评论作者（BUG-002 里被删评论的归属人） |

登录页 `/login`，表单字段 `username`、`password`，登录成功后 Session 里存 `loginUser`。

### 0.3 Postman 保存两份 Cookie

1. Postman → Settings → General，确认 **Cookie jar** 开启；需要看 302 时关闭 **Automatically follow redirects**。
2. 新建 Collection「campus_headline-普通用户」：
   - 新建请求 `POST http://localhost:8080/campus_headline/login`
   - Body → `x-www-form-urlencoded`，键值 `username=student`、`password=123456`，Send；
   - 响应 302，Postman 自动把 `JSESSIONID` 写入 Cookie jar（点上方的 **Cookies** 按钮可看到 `localhost` 下的 JSESSIONID）。
3. 复制该请求，新建 Collection「campus_headline-管理员」，把 `username` 改成 `admin` 再 Send 一次。
4. 之后所有请求都在对应 Collection 内发送，Postman 会自动带上各自的 JSESSIONID；两个身份互不干扰。
5. 如果 Cookie 没自动带上，就在请求 Header 里手动加 `Cookie: JSESSIONID=xxxx`（值从浏览器 F12 → Application → Cookies 复制）。

### 0.4 数据库连接

- Navicat：新建 MySQL 连接，主机 `localhost`、端口 `3306`、用户名/密码同 `jdbc.properties`，数据库 `campus_headline`。
- 命令行：`mysql -u root -p campus_headline`。
- 常用字段口径：
  - `news.status`：`0` 草稿、`1` 已发布、`2` 已审核、`3` 已驳回；
  - `topic.status`、`video.status`：`1` 待审核、`2` 已审核、`3` 已驳回；
  - `comment.target_type`、`news_like.target_type`：`news` / `video` / `topic`，配合 `news_id` 字段做多态关联（该字段实际存的是目标实体 ID）。

### 0.5 截图规范

- 浏览器截图保留地址栏；Postman 截图保留请求方法、完整 URL、Headers 里的 Cookie 是否勾选、响应状态码与响应体。
- 数据库截图保留连接名、库名、执行的 SQL 和结果表格（至少露出关键字段）。
- 文件格式 PNG，文件名与本指南各小节标题完全一致。

```sql

SELECT id, title, status FROM news WHERE id = 7;
```

**操作步骤**

**判定通过**
- 状态码为 403 且响应体包含上述提示文案，同时下一张图的 SQL 显示 `status` 仍为 `0`。

## 4. BUG-004：上传资源 `file:` 前缀问题（2 张）

> 重要说明：`/upload/**` 目前由 `UploadController.serve`（第 31 行 `@GetMapping("/upload/{fileName:.+}")`）处理，它带 Range 分段支持，优先级高于 `springmvc.xml` 里的 `<mvc:resources>`。所以**只把 `file:/` 改回 `file:` 并不能复现 404**，必须临时注释掉这个 Controller 映射，让请求回落到静态资源映射。以下两步都涉及临时改代码，截完务必还原。

### 4.1 先准备一个可访问的上传文件

1. 管理员登录浏览器，进入素材上传页 `http://localhost:8080/campus_headline/material/toUpload`。
2. 上传一张小于 1MB 的图片（表单 action 为 `/material/upload`，字段名 `file`）。
3. 打开 `http://localhost:8080/campus_headline/material/list`，从列表里复制该文件的访问地址，形如 `/upload/8f3a....png`，记下文件名。

### 4.2 `BUG-004-01-upload-404.png`

**前置准备**
- 停止 Tomcat。
- 把 `src/main/resources/springmvc.xml` 第 26-27 行临时改回缺陷状态：

```xml
    <mvc:resources mapping="/upload/**"
                   location="file:${user.home}/campus_upload/"/>
```

- 把 `src/main/java/com/chenxy/controller/UploadController.java` 第 31 行的 `@GetMapping(value={"/upload/{fileName:.+}"})` 注释掉（只注释这一行注解即可，方法体和 import 保留，保证能编译）。

**操作步骤**
1. `mvn clean package`，重新部署 war，`startup.bat` 启动。
2. 浏览器访问 `http://localhost:8080/campus_headline/upload/{第 4.1 步记下的文件名}`。
3. 同时看 Tomcat 控制台的资源映射日志。

**取证**
- 截浏览器：地址栏完整 URL、页面 404 提示（或 Tomcat 的 404 页面）。
- 若控制台有相关告警，可拼一张控制台截图。

**预期结果**
- 请求返回 404，物理文件其实存在 `C:\Users\{用户名}\campus_upload\` 下。

**判定通过**
- 文件确实在磁盘上（可在资源管理器截图对照），但 HTTP 访问为 404。

### 4.3 `BUG-004-02-upload-成功.png`

**前置准备**

  - `springmvc.xml` 第 27 行改回 `location="file:/${user.home}/campus_upload/"`；
  - 取消 `UploadController` 第 31 行注解的注释。

- **判定**：未跳转 `/index`，响应中无 `loginUser` 相关的首页内容，SQL 对照显示该条件本可匹配全部 4 个账号。

### 5.8 `TC-H03.png`（未登录访问新闻写接口）

- **前置**：Postman 新开一个**不带 Cookie** 的 Collection（或在请求里关掉 Cookie）。
- **步骤**：
  1. 新建 `POST /news/add`；
  2. Header 增加 `Accept: application/json`；
  3. Body `x-www-form-urlencoded`：`title=未登录测试`、`content=test`；
  4. 发送。

- **取证**：截 Status=**401 Unauthorized**、请求头中的 `Accept: application/json`、无 `Set-Cookie`。

- **预期**：`LoginInterceptor` 先于 `RoleInterceptor` 执行，未登录直接 401，不会进入 Controller。
- **判定**：401（不是 403、不是 200）。
- **补充**：如果直接在浏览器地址栏访问，表现是 302 跳转 `/login`——因为拦截器只在 `Accept` 含 `application/json` 时返回 401，截图请统一用 Postman 的 401 这一种。
