# BUG-002 修复证据：评论删除缺少身份校验

> 缺陷单：[../缺陷清单.md](../缺陷清单.md) BUG-002
> 验证用例：TC-E05、TC-H05（普通用户删除他人评论）
> 涉及文件：`src/main/java/com/chenxy/controller/CommentController.java`、`src/main/java/com/chenxy/service/impl/CommentServiceImpl.java`

## 一、缺陷表现

评论删除接口 `/comment/delete` 在 LoginInterceptor 保护范围内（仅要求登录），RoleInterceptor 未配置该路径；同时删除逻辑未校验「当前用户是否为评论作者或管理员」，任何登录用户只要拿到 commentId 就能删除他人评论，数据库记录被物理删除且无提示。

## 二、修复前逻辑（缺陷状态）

缺陷版本中，删除请求经登录校验后直接按 id 执行删除，没有作者/管理员判断：

```java
// 修复前（缺陷逻辑，无身份校验）
this.commentService.delete(id);
```

说明：仓库 git 历史中 CommentController 与 CommentServiceImpl 都只有一次初始提交，没有可检出的修复前文件，因此以上为按缺陷单根因定位还原的关键差异行，其余代码与当前一致。

## 三、修复后代码（当前仓库代码）

`CommentController.delete`（第 34-44 行）从 Session 取当前用户，把 userId 与是否管理员一并传给 Service：

```java
    @GetMapping(value={"/delete"})
    public String delete(@RequestParam Integer id, @RequestParam(required=false) Integer targetId, @RequestParam(required=false) Integer newsId, @RequestParam(required=false, defaultValue="news") String targetType, HttpSession session) {
        Integer realTargetId = targetId != null ? targetId : newsId;
        User user = (User)session.getAttribute("loginUser");
        if (user == null || realTargetId == null) {
            return "redirect:/login";
        }
        boolean admin = "admin".equals(user.getRole());
        this.commentService.delete(id, user.getId(), admin);
        return this.redirectToDetail(realTargetId, targetType);
    }
```

`CommentServiceImpl.delete`（第 82-91 行）执行身份校验，非作者且非管理员时直接返回 false，不触碰数据库：

```java
    public boolean delete(Integer id, Integer userId, boolean admin) {
        Comment comment = (Comment)this.commentMapper.selectById(id);
        if (comment == null) {
            return false;
        }
        if (!admin && !comment.getUserId().equals(userId)) {
            return false;
        }
        return this.commentMapper.deleteById(id) > 0;
    }
```

## 四、验证方式与预期结果

1. 用户 A 登录并发表评论，记录 commentId；
2. 用户 B 登录，Postman 携带 B 的 JSESSIONID 发送 `/campus_headline/comment/delete?id={A的commentId}&targetId=1&targetType=news`；
3. 预期删除未生效，数据库中该评论仍存在（SQL 前后对比 comment 表行数与主键）；
4. 用户 A 删除自己的评论、admin 删除任意评论，预期均删除成功；
5. 对照用例 TC-E05、TC-H05 回归，结果记为 PASS。
