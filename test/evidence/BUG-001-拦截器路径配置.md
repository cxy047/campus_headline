# BUG-001 修复证据：RoleInterceptor 路径与 NewsController 实际接口不匹配

> 缺陷单：[../缺陷清单.md](../缺陷清单.md) BUG-001
> 验证用例：TC-B10（普通用户直接请求审核接口）
> 涉及文件：`src/main/resources/springmvc.xml`（RoleInterceptor 配置）、`src/main/java/com/chenxy/controller/NewsController.java`

## 一、缺陷表现

NewsController 实际暴露的审核相关接口为：

```java
    @GetMapping("/submitAudit")
    public String submitAudit(Integer id) { ... }

    @GetMapping("/auditPass")
    public String auditPass(Integer id) { ... }

    @GetMapping("/auditReject")
    public String auditReject(Integer id) { ... }
```

而 springmvc.xml 中 RoleInterceptor 配置的三个路径在 Controller 里并不存在，导致 `/news/auditPass`、`/news/auditReject` 只经过 LoginInterceptor（仅校验登录态），任何已登录的普通用户都能直接审核新闻。

## 二、修复前配置（springmvc.xml 第 62-64 行，缺陷状态）

```xml
            <mvc:mapping path="/news/audit"/>
            <mvc:mapping path="/news/publish"/>
            <mvc:mapping path="/news/draft"/>
```

上述三个 path 与 NewsController 的真实映射无一匹配，等同于该拦截器对新闻审核接口完全失效。

## 三、修复后配置（当前仓库代码，springmvc.xml 第 62-64 行）

```xml
            <mvc:mapping path="/news/submitAudit"/>
            <mvc:mapping path="/news/auditPass"/>
            <mvc:mapping path="/news/auditReject"/>
```

## 四、验证方式与预期结果

1. 以普通用户（role=user）登录，F12 取 Cookie 中的 JSESSIONID；
2. Postman 发送 `GET http://localhost:8080/campus_headline/news/auditPass?id=5`，携带该 Cookie；
3. 预期返回 403 页面，内容为「无权访问：仅管理员可执行此操作」，数据库 news.status 不发生变化；
4. 以 admin 账号重复步骤 2，预期审核成功、状态变为已审核，管理列表正常跳转；
5. 对照用例 TC-B10 执行回归，结果记为 PASS。

## 五、备注

仓库 git 历史中 `springmvc.xml` 只有一次初始提交，因此「修复前」片段即该文件中原始的三行配置，未做改写；「修复后」片段与当前仓库代码逐字一致。
